# Introduction to LanGraph
## Type Annotations
### Dictionary 
1. **Normal dictionary :**
    ```python
    movie = {"name": "A silent voice", "year": "2016"}
    ```
    - PROS : 
        - Allows for efficient data retrieval based on unique keys
        - Flexible and easy to implement 
    - CONS : 
        - Leads to challenges in ensuring that the data is paricular structure specially for larger projects
        - Doen't check if the data is of correct type or structure 
    - The fact that it does not check for correct type or structure can be the source of a log of logical errors in a specially large projects and it becomes quite a headache to identify because it is quite a small detail.

2. **Typed dictionary :**
    - A typed dictionary solves the problem related to type and structural correctness that was not being checked by a normal dictionary and was causing a lot of issues in large projects 
    - Here is an example on how you create a typed dictionary in python
    ```python
        # This is how you create a typed dictionary in python
        class Movie(TypedDict):
            name : str
            year : int
        # This is how you use the typed dictionary once it has been created 
        movie = Movie(name="A silent voice",year=2016)
    ```
    - This type of annotations are extensively used in LanGraph for defining states
