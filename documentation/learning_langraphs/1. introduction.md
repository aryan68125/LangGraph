# Introduction to LanGraph
## Type Annotations
### Dictionary 
1. **Normal dictionary :**
    ```python
    movie = {"name": "A silent voice", "year": "2016"}
    ```
    - PROS : 
        - Allows for efficient data retrieval based on unique keys
        - Flexible and easy to implement 
    - CONS : 
        - Leads to challenges in ensuring that the data is paricular structure specially for larger projects
        - Doen't check if the data is of correct type or structure 
    - The fact that it does not check for correct type or structure can be the source of a log of logical errors in a specially large projects and it becomes quite a headache to identify because it is quite a small detail.

2. **Typed dictionary :**
    - A typed dictionary solves the problem related to type and structural correctness that was not being checked by a normal dictionary and was causing a lot of issues in large projects 
    - Here is an example on how you create a typed dictionary in python
    ```python
        # This is how you create a typed dictionary in python
        class Movie(TypedDict):
            name : str
            year : int
        # This is how you use the typed dictionary once it has been created 
        movie = Movie(name="A silent voice",year=2016)
    ```
    - This type of annotations are extensively used in LanGraph for defining states
    - PROS : 
        - Type safety : because we explicitely defined what should be in this data structure
        - Enhanced readability : Makes debugging easier and makes code more understandable

### Union
- This is how you write a union in python 
```python
from typing import Union
def square(x: Union[int,float]) -> float:
    return x * x

x = 5 # this is fine because x is an integer
x = 1.234 # this is also fine because it is a float
x = "I am ROLLEX" # this will fail because it is a string
```
- Pros : 
    - Union lets you say that a value can be more than one type
    - Flexible and easy to code
    - Type Safety as it can provide hints to help catch incorrect usage
- The makers of Langchain and Langraph actually used **Union** quite extensively when making these libraries.

### Optional
- This is how you write optional in python as shown below
```python
from typing import Optional
def nice_message(name : Optional[str]) -> None:
    if name is None:
        print("Hey random person!")
    else:
        print(f"Hi there {name}!")
```
- In this case "name" can be either String or None!
- It cannot be anything else

### Any
- This is how you write and use Any in python
```python
from typing import Any
def print_value(x:Any):
    print(x)
print_value("I am so rich that I am BATMAN")
```
- Anything and everything is allowed!

### Lambda function
- This is how you create a lambda function in python
```python
nums = [1,2,3,4]
squares = list(map(lambda x : x * x, nums))
```
- So what does this code do?
    ```python
         map(lambda x : x * x, nums)
    ```
    - This maps each values that are there in the ``nums`` list and squares it one by one like this ``1,4,9,16``
    - The ``list(map(...))`` that is present outside the map converts the result into a list
- Lambda functions are nothing but a shortcut to write small and efficient function

## Elements in Langraph
### State 
- State is a shared data strucutre that holds the current information or context of the entire application.
- In simple terms , it is like the application's memory, keeping track of the variables and data that node can access and modify as they execute.

### Nodes
- Nodes are individual functions or operations that perform specific tasks within the graph.
- Each node recieves input (often current state), processes it, and produces an output or an updated state.

### Graph
- A Graph in LangGraph is the overarching structure that maps out how different tasks (nodes) are connected and executed.
- It visually represents the workflow , showing the sequence and conditional paths between various operations.

### Edges 
- Edges are the connections between nodes that determine the flow of execution.
- They tell us which node should be executed next after the current one completes its task.
#### Conditional Edge : 
- Conditional edge are specialized connections that decide the next node to execute based on specific conditions or logic applied to the current state.

### Start Node
- Start node is a virtual entry point in LangGraph marking where the workflow begins.
- It doesn't perform any positions itself but serves as the designated starting position for the graph's execution.

### End Node
- The End node signifies the conclusion of the workflow in LangGraph.
- Upon reaching this node, the graph's execution stops, indicating that all intended processes have been completed.

### Tools
- Tools are specialized functions or utilities that nodes can utilize to perform specific tasks such as fecthing data from an API
- They enhance the capabilities of nodes by providing additional functionalities.
- Nodes are part of the graph strucutre, while tools are functionalities used within nodes.

### Tool Node 
- A ToolNode is just a special kind of node whose main job is to run a tool.
- It connects the tool's output into the State so other nodes can use that information.

### State Graph
- A StateGraph is a class in LangGraph used to build and compile the graph structure.
- It manages the nodes, edges and the overall state, ensuring that the workflow operates in a unified way and that data flows correctly between components.

### Runnable
- A Runnable in LangGraph is a standardized, executable component that performs a specific task within an AI workflow.
- It serves as a fundamental building block, allowing for us to create modular systems.
- Difference between a Runnable and a Node
    - Runnable : A runnable can represent various operations
    - Node : A nonde in LangGraph typically recieves a state. It performs an action on them and then updates the state.
